# 5. Магические фильтры F

Магические фильтры — способ описывать условия прямо в декораторе, без вспомогательных функций. Это делает код короче и понятнее.

## Идея

Обычный фильтр — это функция, возвращающая `True` или `False`. Писать отдельную функцию для каждого простого условия утомительно. Магический фильтр `F` позволяет задать условие прямо в декораторе:

```python
from aiogram import F

@router.message(F.text == "привет")
async def greet(message: Message):
    await message.answer("Привет!")
```

`F.text == "привет"` — это объект, который ведёт себя как фильтр. Внутри он сравнивает `message.text` со строкой и возвращает результат.

Как это работает под капотом: `F` — это объект-обёртка над событием. Обращаясь к атрибутам (`F.text`, `F.from_user.id`), вы как будто говорите: «Когда придёт событие, возьми из него поле `text`». А операции `==`, `!=`, `in_` превращают это в проверку. В момент обработки aiogram вычисляет результат и решает, подходит хендлер или нет.

## Что можно проверить

Через `F` доступны все поля события. Например, для `message`:

- `F.text` — текст сообщения.
- `F.photo` — есть ли фото.
- `F.video` — есть ли видео.
- `F.document` — есть ли документ.
- `F.from_user.id` — ID отправителя.
- `F.from_user.username` — username.
- `F.chat.id` — ID чата.
- `F.chat.type` — тип чата (`private`, `group`, `supergroup`, `channel`).
- `F.content_type` — тип контента.
- `F.message_id` — ID сообщения.

Для `callback_query`:

- `F.data` — данные кнопки.
- `F.message` — сообщение, к которому прикреплена кнопка.
- `F.from_user.id` — кто нажал.

Полный список полей — в документации по типу события. Общее правило: если у объекта есть поле `foo`, то `F.foo` тоже работает.

## Операции сравнения

Работают привычные операции: `==`, `!=`, `<`, `>`, `in`.

```python
@router.message(F.text == "меню")
@router.message(F.text != "секрет")
@router.message(F.from_user.id == 123456789)
@router.message(F.message_id > 1000)
```

Метод `.in_()` — это проверка на вхождение. Он появился именно для магических фильтров, потому что `in` в Python нельзя перегрузить так, чтобы работало и слева, и справа.

```python
@router.message(F.text.in_(["да", "конечно", "ага"]))
@router.message(F.from_user.id.in_([123, 456, 789]))
```

Есть также `.not_in()` — обратная проверка:

```python
@router.message(F.text.not_in_(["спам", "реклама"]))
```

## Строковые методы

Можно использовать строковые методы прямо в фильтре:

```python
@router.message(F.text.startswith("заказ"))
@router.message(F.text.endswith(".jpg"))
@router.message(F.text.contains("важно"))
@router.message(F.text.lower() == "привет")
@router.message(F.text.isdigit())
@router.message(F.text.len() > 100)
```

Все методы строк Python доступны через `F.text`. Это работает за счёт того, что `F.text` возвращает объект, который перехватывает вызовы методов и превращает их в условия.

Полный список доступных методов: `startswith`, `endswith`, `contains`, `lower`, `upper`, `strip`, `isdigit`, `isalpha`, `isalnum`, `len`, `regex`, `replace`. Полный перечень — в исходниках aiogram (`aiogram.filters.magic`).

### Регулярные выражения

Для сложных шаблонов есть `.regex()`:

```python
import re

@router.message(F.text.regex(r"^\d{4}$"))  # ровно 4 цифры
async def on_code(message: Message):
    await message.answer("Похоже на код подтверждения")

@router.message(F.text.regex(re.compile(r"^\+7\d{10}$")))  # российский номер
async def on_phone(message: Message):
    await message.answer("Похоже на телефон")
```

## Проверка наличия

Иногда нужно проверить, что поле существует, а не сравнивать его. Для этого используют приведение к `bool`:

```python
@router.message(F.photo)          # есть фото
@router.message(F.video)          # есть видео
@router.message(F.document)       # есть документ
@router.message(F.from_user.username)  # у пользователя есть username
```

Как это работает: `F.photo` без операции возвращает объект, который при проверке конвертируется в `bool` — есть поле или нет.

Обратное — «нет поля» — не работает напрямую. Если хотите поймать «сообщение без фото», используйте `~`:

```python
@router.message(~F.photo)  # сообщение без фото
```

## Комбинации условий

Оператор `&` — логическое «И». Оператор `|` — логическое «ИЛИ». Оператор `~` — отрицание. Скобки работают как обычно.

```python
@router.message(F.text.startswith("show") & F.text.endswith("example"))
@router.message(F.text == "hi" | F.text == "hello")
@router.message((F.text == "да") | (F.text == "нет"))
@router.message(F.photo & F.caption.startswith("отчёт"))
@router.message(~F.from_user.is_bot)
```

Комбинировать можно сколько угодно условий:

```python
@router.message(
    (F.text == "да") | (F.text == "нет"),
    F.chat.type == "private",
)
```

Скобки важны: `F.a == 1 | F.b == 2` распарсится не так, как вы ожидаете. Всегда оборачивайте каждое условие в скобки, если используете `|`.

## Частые ошибки

**Ошибка 1. Один знак `=` вместо `==`.**

```python
@router.message(F.text = "привет")  # SyntaxError
@router.message(F.text == "привет")  # ок
```

В Python `=` — это присваивание, `==` — сравнение. Внутри декоратора присваивание синтаксически невозможно.

**Ошибка 2. `and` и `or` вместо `&` и `|`.**

```python
@router.message(F.text == "да" and F.text == "нет")  # не сработает
@router.message((F.text == "да") & (F.text == "нет"))  # ок
```

`and` и `or` работают с булевыми значениями, а магические фильтры — это объекты. Результат будет некорректным. Всегда используйте `&`, `|`, `~`.

**Ошибка 3. `.in_()` с отдельными аргументами вместо списка.**

```python
@router.message(F.text.in_("да", "нет"))     # TypeError
@router.message(F.text.in_(["да", "нет"]))   # ок
```

`.in_()` принимает один итерируемый объект — список, кортеж, множество.

**Ошибка 4. Сравнение с `None` через `==`.**

```python
@router.message(F.text == None)  # работает, но не рекомендуется
@router.message(~F.text)         # идиоматично
```

**Ошибка 5. `F.text` для сообщений без текста.**

```python
@router.message(F.text.lower() == "привет")  # упадёт, если это фото без подписи
```

`F.text` для сообщения с фото и без подписи вернёт `None`, а `None.lower()` выбросит исключение. Если есть риск — сначала проверяйте наличие поля:

```python
@router.message(F.text & (F.text.lower() == "привет"))
```

## Порядок имеет значение

Как и в главе 4: магические фильтры — это те же фильтры, они срабатывают по очереди. Если у вас есть общий `F.text`, он перехватит всё, что до него дошло.

```python
# Перехватит всё
@router.message(F.text)
async def any_text(message: Message):
    pass

@router.message(F.text == "помощь")
async def cmd_help(message: Message):
    pass  # никогда не вызовется
```

Правильно — сначала узкие условия, потом широкие.

## Магические фильтры против обычных

Магические фильтры удобны для простых условий. Для сложной логики — например, проверки пользователя в базе данных — лучше писать кастомный фильтр (глава 4).

Правило простое:

| Ситуация | Что использовать |
|---|---|
| Сравнение с константой (`F.text == "да"`) | `F` |
| Проверка вхождения (`F.text.in_([...])`) | `F` |
| Строковый метод (`F.text.startswith(...)`) | `F` |
| Проверка наличия поля (`F.photo`) | `F` |
| Простая комбинация (`&`, `\|`, `~`) | `F` |
| Проверка в БД | Кастомный фильтр |
| Запрос к API | Кастомный фильтр |
| Сложная логика с несколькими шагами | Кастомный фильтр |

Не пытайтесь впихнуть в одну строку всё — код станет нечитаемым. Если условие требует комментария, чтобы понять, что оно делает, — пишите класс.

## Совет

Магические фильтры можно комбинировать с обычными. Например, `Command("ban")` — это тоже фильтр, и он отлично работает в одном декораторе с `F`:

```python
@router.message(Command("ban"), F.chat.type == "supergroup")
async def cmd_ban(message: Message):
    ...
```

Все фильтры в декораторе объединяются логическим «И» — хендлер сработает, только если подходят все. Это позволяет строить точные условия без кастомных классов.
