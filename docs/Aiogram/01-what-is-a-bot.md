# 1. Что такое Telegram-бот и как он работает

Прежде чем писать код, стоит понять, с чем именно мы работаем. Telegram-бот — это не приложение внутри мессенджера, как многие думают. Это **обычная программа на вашем сервере**, которая общается с Telegram через HTTP API.

## Как устроено взаимодействие

Telegram Bot API — это HTTPS-интерфейс, через который ваша программа отправляет и получает сообщения. Когда пользователь пишет боту, Telegram сохраняет это сообщение у себя, а затем ваш бот может его забрать — либо запросом, либо через push от Telegram.

Отсюда вытекают два принципиально разных способа работы:

- **Polling** — ваш бот сам периодически спрашивает Telegram: «Есть новые сообщения?».
- **Webhook** — вы сообщаете Telegram свой URL, и он сам отправляет туда HTTP-запросы при каждом новом сообщении.

Оба способа приводят к одному результату: ваш код получает объект **Update** — структуру данных с информацией о том, что произошло (пришло сообщение, нажали кнопку, зашли в чат).

## Что такое Update

Update — это JSON-объект. Он может содержать разные вещи: новое сообщение, нажатие на inline-кнопку, изменение статуса участника чата, запрос на оплату. У каждого типа Update есть своё поле. Например, обычное сообщение от пользователя приходит в поле `message`, а нажатие на inline-кнопку — в поле `callback_query`.

Ваш код должен разобрать эти Update'ы и решить, что с ними делать. Именно этим занимается aiogram — принимает поток Update'ов и вызывает нужные функции в зависимости от их содержимого.

## BotFather и токен

Чтобы Telegram знал, что вы — это вы, каждому боту выдаётся **токен** — уникальная строка. Она работает как пароль: любой, кто её знает, может действовать от имени бота. Токен выдаёт **@BotFather** — официальный бот для управления ботами.

В токене зашита вся информация о боте: его ID и секретный ключ для подписи запросов. Поэтому токен — это не «просто строка для входа», а полноценный ключ доступа, и хранить его нужно соответственно: в переменных окружения, а не в коде.
