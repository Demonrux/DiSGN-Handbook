# 1. Что такое Telegram-бот и как он работает

Прежде чем писать код, стоит понять, с чем именно мы работаем. Telegram-бот — это не приложение внутри мессенджера, как многие думают. Это **обычная программа на вашем сервере**, которая общается с Telegram через HTTP API.

## Как устроено взаимодействие

Telegram Bot API — это HTTPS-интерфейс, через который ваша программа отправляет и получает сообщения. Когда пользователь пишет боту, Telegram сохраняет это сообщение у себя, а затем ваш бот может его забрать — либо запросом, либо через push от Telegram.

Отсюда вытекают два принципиально разных способа работы:

- **Polling** — ваш бот сам периодически спрашивает Telegram: «Есть новые сообщения?».
- **Webhook** — вы сообщаете Telegram свой URL, и он сам отправляет туда HTTP-запросы при каждом новом сообщении.

Оба способа приводят к одному результату: ваш код получает объект **Update** — структуру данных с информацией о том, что произошло (пришло сообщение, нажали кнопку, зашли в чат).

## Жизненный цикл Update

Что происходит, когда пользователь пишет боту:

```
Пользователь
    │
    ▼
┌─────────────┐
│  Telegram   │  формирует Update (JSON)
└─────────────┘
    │
    ▼
┌─────────────┐
│     Bot     │  забирает Update (polling или webhook)
└─────────────┘
    │
    ▼
┌─────────────┐
│ Dispatcher  │  решает, какой роутер должен обработать
└─────────────┘
    │
    ▼
┌─────────────┐
│   Router    │  проверяет фильтры хендлеров по порядку
└─────────────┘
    │
    ▼
┌─────────────┐
│   Handler   │  выполняет логику и отвечает пользователю
└─────────────┘
```

При webhook вся цепочка занимает миллисекунды. При polling добавляется задержка до нескольких секунд — бот сам ходит за обновлениями с определённым интервалом. Понимание каждого шага критично для отладки: если бот «молчит», проблема может быть на любом уровне — от неверного токена до неправильного фильтра.

## Что такое Update

Update — это JSON-объект. Он может содержать разные вещи: новое сообщение, нажатие на inline-кнопку, изменение статуса участника чата, запрос на оплату. У каждого типа Update есть своё поле. Например, обычное сообщение от пользователя приходит в поле `message`, а нажатие на inline-кнопку — в поле `callback_query`.

Пример Update с обычным сообщением (сокращённо):

```json
{
  "update_id": 123456789,
  "message": {
    "message_id": 42,
    "from": {
      "id": 987654321,
      "is_bot": false,
      "first_name": "Иван",
      "username": "ivan"
    },
    "chat": {
      "id": 987654321,
      "type": "private"
    },
    "date": 1700000000,
    "text": "Привет!"
  }
}
```

Ваш код должен разобрать эти Update'ы и решить, что с ними делать. Именно этим занимается aiogram — принимает поток Update'ов и вызывает нужные функции в зависимости от их содержимого.

## Polling vs Webhook

Оба способа рабочие, но подходят для разных задач. Вот сравнение:

| Критерий | Polling | Webhook |
|---|---|---|
| Сложность настройки | Низкая — только токен | Средняя — нужен HTTPS, домен, сертификат |
| Нагрузка на сервер | Постоянные запросы к Telegram | Запросы только при новых событиях |
| Требуется белый IP / домен | Нет | Да |
| Скорость реакции | Задержка до нескольких секунд | Мгновенная |
| Работа за NAT / firewall | Работает | Требует внешнего доступа |
| Идеально для | Разработки, малых и средних ботов | Продакшена, высокой нагрузки |
| Запуск нескольких экземпляров | Нельзя (конфликт `getUpdates`) | Можно (с балансировкой) |

**Практическое правило:** начинайте с polling. Когда бот вырастет и потребует мгновенной реакции или горизонтального масштабирования — переходите на webhook. aiogram поддерживает оба режима без изменения логики хендлеров.

## BotFather и токен

Чтобы Telegram знал, что вы — это вы, каждому боту выдаётся **токен** — уникальная строка. Она работает как пароль: любой, кто её знает, может действовать от имени бота. Токен выдаёт **@BotFather** — официальный бот для управления ботами.

В токене зашита вся информация о боте: его ID и секретный ключ для подписи запросов. Формат токена: `<bot_id>:<secret>`, например:

```
123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
```

Первая часть — ID бота, вторая — секретный ключ. Поэтому токен — это не «просто строка для входа», а полноценный ключ доступа.

## Как хранить токен

Никогда не коммитьте токен в Git. Ни в коде, ни в конфигах, ни в тестах. Даже если репозиторий приватный — рано или поздно он станет публичным, либо токен утечёт через историю коммитов.

Правильный способ — **переменные окружения**. Создайте файл `.env` в корне проекта:

```env
BOT_TOKEN=123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw
```

И добавьте `.env` в `.gitignore`:

```gitignore
.env
.venv/
__pycache__/
*.pyc
```

Читать токен в коде можно двумя способами.

**Вариант 1 — через `python-dotenv`:**

```python
import os
from dotenv import load_dotenv

load_dotenv()
BOT_TOKEN = os.getenv("BOT_TOKEN")
```

**Вариант 2 — через `pydantic-settings` (рекомендуется для больших проектов):**

```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    bot_token: str
    admin_ids: list[int] = []

    model_config = SettingsConfigDict(env_file=".env")

settings = Settings()
```

`pydantic-settings` автоматически читает `.env`, приводит значения к нужным типам и падает с понятной ошибкой, если переменная не задана. Это надёжнее, чем `os.getenv`, который вернёт `None` и упадёт где-то позже.

## 💡 Совет

Если токен всё-таки утёк (например, случайно попал в публичный репозиторий) — немедленно отзовите его через `@BotFather`: команда `/revoke`. Старый токен перестанет работать, вы получите новый. Все, кто им пользовался, потеряют доступ к боту.
